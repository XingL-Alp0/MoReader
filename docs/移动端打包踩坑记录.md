# 移动端打包踩坑记录

把墨阅（Electron 桌面版）搬到 Android 的全过程记录。按「现象 → 原因 → 解决 → 预防」整理，最后附一份下次移植的检查清单。

面向的读者：想用同一套 Web 渲染层再做一次移动端封装的自己。文档导航见 [`README.md`](README.md)。

---

## 0. 先确定技术路线

**Electron 不能打 APK。** Electron 没有官方 Android 运行时，`electron-builder` 也只支持 Windows / macOS / Linux。如果目标是手机，只有三条路：

| 路线 | 适用 | 代价 |
| --- | --- | --- |
| **Capacitor**（本次采用） | 已有 Web 渲染层，想复用 ~90% 代码 | 写平台适配层 + 移动端 UI 适配 |
| 原生 WebView 壳（Kotlin） | 只需要最小桥接、不想要 npm 插件体系 | 所有平台能力自己实现 |
| PWA / TWA | 主要场景是阅读 | 需要 HTTPS 托管；本地文件能力弱 |

关键前提：渲染层必须**没有**直接依赖 `window.moread`（Electron preload 注入的桥）。只要先把这段抽象成一层 API，换壳成本会从「重写」降到「补适配器」。

本次结果：`dist/` 原样复用，新增约 500 行平台适配 + 约 700 行原生插件，APK 4.7 MB。

## 1. 环境与工具链

### 1.1 `sdkmanager` 已弃用，新 CLI 参数不一样

**现象**

```
WARNING: The SDK Manager CLI tool (sdkmanager) is deprecated. Android CLI will be used instead.
Package platforms not found.
Package android-36 not found.
Package build-tools not found.
```

**原因**：新版 `cmdline-tools`（本次 `commandlinetools-win-16111833`）把包名改成了 `android sdk install` 的子命令，旧的 `sdkmanager 'platforms;android-36'` 不再识别。

**解决**

```powershell
$sdk = "D:\dev\tools\android-sdk"
& "$sdk\cmdline-tools\latest\bin\android.exe" --sdk=$sdk sdk install `
  'platforms;android-36' 'build-tools;36.0.0' 'platform-tools'
```

**预防**：先跑 `android.exe sdk --help` 看当期命令，不要照抄老博客。

### 1.2 Gradle 发行包下载卡死

**现象**：`gradlew.bat` 停在 `Downloading https://services.gradle.org/distributions/gradle-8.14.3-all.zip`，`.part` 文件一直是 0 字节。

**原因**：`services.gradle.org` 在部分网络下不可达（本机实测超时），不是 Gradle 本身的问题。

**解决**：改 `android/gradle/wrapper/gradle-wrapper.properties`：

```properties
distributionUrl=https\://mirrors.cloud.tencent.com/gradle/gradle-8.14.3-all.zip
networkTimeout=60000
```

依赖库同样容易卡，在 `android/build.gradle` 里加阿里云镜像（放在 `google()` 之前）：

```gradle
maven { url 'https://maven.aliyun.com/repository/google' }
maven { url 'https://maven.aliyun.com/repository/central' }
maven { url 'https://maven.aliyun.com/repository/gradle-plugin' }
```

**预防**：首次构建预留 200 MB+ 下载量；`.gradle/wrapper/dists` 里的 `.part` 一直是 0 就说明镜像不通，别干等。

### 1.3 JDK 版本：必须 21

**现象**

```
BUG! exception in phase 'semantic analysis' in source unit '_BuildScript_'
Unsupported class file major version 69
```

**原因**：`JAVA_HOME` 指向 JDK 25（class 69），而 Gradle 8.14 / AGP 8.13 还不支持这个字节码版本。

**解决**

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21.0.11'
```

本机同时装了 17 / 21 / 25，`java -version` 走 PATH 是 21，但 **Gradle 认 `JAVA_HOME`**，两者不一致时就会踩坑。

**预防**：把 `JAVA_HOME` 写进构建脚本或 `.env`，不要依赖 PATH。

### 1.4 PowerShell 的编码问题会毁了资源文件

**现象**：`capacitor.config.json` 里的应用名变成 `澧ㄩ槄 MoRead`，`strings.xml` 同样乱码。

**原因**：中文参数经 PowerShell 传给 Node CLI 时按 ANSI（cp936）走了一遍；同理，用 `Get-Content -Raw` + `Set-Content` 改 UTF-8 文件会双重编码，而且**不可逆**（cp936 编解码不回环）。

**解决**：所有含中文的配置用编辑工具重写，不要用 PowerShell 批量替换；`.ps1` 存 UTF-8 with BOM。

**预防**：本次连 `README.md` 都被这个操作毁过一次，只能重写。规则：**PowerShell 不碰文本文件**。

## 2. 工程生成（Capacitor）

### 2.1 开发实例与已安装版抢同一份配置

**现象**：开发版启动后直接退出，连 DevTools 端口都连不上；清理 `%APPDATA%\MoRead` 时报文件被占用。

**原因**：已安装的 MoRead 正在运行，持有默认 `userData` 的单实例锁和 leveldb 句柄；新实例拿不到锁就 `app.quit()`。

**解决**：主进程支持 `--user-data-dir`，在 `requestSingleInstanceLock()` **之前**设置：

```js
applyUserDataOverride();          // app.setPath('userData', ...)
const gotLock = app.requestSingleInstanceLock();
```

开发脚本加 `-UserDataDir` / `-ImportTheme` 参数，两者互不干扰。

**预防**：桌面端调试前先确认没有正式版在跑；给调试实例固定一个独立 profile 目录。

### 2.2 每次改渲染层都要 `cap sync`

**现象**：改了 `app.js` 重新打包，装到手机上还是旧行为。

**原因**：Capacitor 把 `webDir`（`dist/`）**复制**到 `android/app/src/main/assets/public`，不是引用。

**解决**：`npm run android:sync` = `build` + `cap sync` + 清理 sourcemap（`scripts/clean-android-assets.js`）。

**预防**：把 sync 串进 build 脚本，别手动分两步；`android/.gitignore` 已忽略 `assets/public`，CI 上必须重新 sync。

## 3. 原生插件（文件、Intent、打印）

### 3.1 从别处打开的文档只有只读授权

**现象**：文件管理器点开 `.md` → 改几个字 → 保存失败。新建文档保存也失败。

**原因**有两个，都很隐蔽：

1. `pick()` 的 Intent 没申请写权限，`ACTION_OPEN_DOCUMENT` 给的授权可能只有读；`openOutputStream` 抛 `SecurityException`。
2. 新建文档的 `doc.path` 是 **`null`**（不是 `""`），适配层里 `path.startsWith(...)` 直接抛 `Cannot read properties of null`。解构默认值 `{ path = "" }` 只对 `undefined` 生效，对 `null` 无效。

**解决**

```js
const path = String(payload.path || "");
```

```java
intent.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION
    | Intent.FLAG_GRANT_WRITE_URI_PERMISSION
    | Intent.FLAG_GRANT_PERSISTABLE_URI_PERMISSION);
```

`openOutputStream` 依次尝试 `wt` / `w` / `rwt`，各家 provider 支持的模式不同。

**预防**：适配层所有来自渲染层的字符串参数先归一化；平台能力要有兜底路径，不能假设「一定能写」。

### 3.2 保存必须做三层兜底

单一路径一定会失败，最终实现：

| 层级 | 条件 | 做法 |
| --- | --- | --- |
| 1 | 有写权限 | `write(uri)` 原地写 |
| 2 | 只读 / 写入被拒 | `createDocument()` 走系统「另存为」，结果带 `notice` 提示 |
| 3 | 另存为不可用（`NO_SAVER`） | 写入 `files/saved/` + 拉起分享面板，让用户存到「文件」或云盘 |

第 3 层用 `FileProvider` 生成 content URI，**必须**在 `res/xml/file_paths.xml` 声明对应目录：

```xml
<files-path name="app_files" path="." />
```

漏了会报 `Failed to find configured root that contains ...`。Capacitor 默认模板只有 `external-path` 和 `cache-path`，而应用私有文件在 `files-path` 下。

**预防**：任何「写文件」入口（保存、导出 HTML/TXT、导出主题包）都要接同一套兜底，不要只修主路径。

### 3.3 系统文档选择器可能根本不存在

**现象**：HarmonyOS NEXT 的 Android 转译环境下，点「导入主题包」没有任何反应。

**原因**：兼容层没有可用的 `DocumentsUI`，`ACTION_OPEN_DOCUMENT` / `ACTION_GET_CONTENT` 都拉不起来。

**解决**：三层降级

1. `ACTION_OPEN_DOCUMENT`
2. `ACTION_GET_CONTENT`
3. WebView 的 `<input type="file">`（这个在兼容层里通常可用）

从 `<input>` 拿到的文件没有真实路径，注册成 `webfile://` 伪 URI 参与内存读取；保存时这类文档自动走「另存为」。

**预防**：移动端不要把「系统选择器可用」当作前提；同时给「文件管理器直接打开 `.zip`」留一条独立入口。

### 3.4 Intent 注册：只写 MIME 不够

**现象**：文件管理器里 `.md` 不出现在「打开方式」；`.zip` 完全没入口。

**解决**：MIME + `pathPattern` + `SEND` 三件套。

```xml
<data android:scheme="content" android:mimeType="text/markdown" />
<data android:scheme="content" android:mimeType="application/octet-stream"
      android:pathPattern=".*\\.md" />
```

很多文件管理器把 `.md` / `.zip` 报成 `application/octet-stream`，只按 MIME 匹配会漏。再加一个 `ACTION_SEND`，用户就能从「分享」进来。

回调侧：`initial()` 和 `documentOpen` 事件都要带 `mime`，渲染层才能把 zip 路由到「导入主题」而不是「当文档打开」。

**预防**：`pathPattern` 里的反斜杠要写两次（XML + Java 转义）；`ACTION_SEND` 用 `EXTRA_STREAM` 取 URI。

### 3.5 大文件 Base64 直接把渲染进程搞崩

**现象**：导入 1.98 MB 的主题包，界面无反应，日志停在「解码前」，随后 `Renderer process crashed`。

**原因**：`atob()` 处理约 2 MB 的字符串时内存峰值过高，Electron / Android WebView 都会崩。小包（几百 KB）不会触发，所以一直没暴露。

**解决**：手写查表解码，逐字节输出，避免大字符串中间态。

```js
const BASE64_LOOKUP = /* 256 项查表 */;
function base64ToBytes(value) { /* 逐 charCode 组装，跳过换行 */ }
```

反向的 `bytesToBase64` 保持分块 `String.fromCharCode`（每块 0x8000），也不要用 `String.fromCharCode(...hugeArray)`。

**预防**：跨桥传输二进制超过 1 MB 时先怀疑 Base64 路径；能在原生侧完成的解析（读 zip 目录）就不要搬回 JS。

### 3.6 PDF 与打印

桌面用 `webContents.printToPDF`；Android 没有等价 API，改成 `PrintManager` + `WebView.createPrintDocumentAdapter`，走系统打印/另存为 PDF。

**注意**：打印要在 UI 线程调用，且 `getBridge().getWebView()` 可能为 null（WebView 未就绪）。

## 4. 渲染层适配

### 4.1 先抽象 API，再谈换壳

```
src/renderer/platform/index.js   →  api = window.moread || createAndroidApi()
src/renderer/platform/android.js →  Capacitor 插件实现
```

Electron 下直接返回 preload 桥，桌面版零改动。**不要**在业务代码里直接写 `window.moread`，否则换壳时要改几十处。

### 4.2 文件路径的两种语义

| 场景 | 桌面 | Android |
| --- | --- | --- |
| 文档路径 | `D:\docs\a.md` | `content://com.android.../123` |
| 主题资源 | `%APPDATA%\MoRead\...` | `file:///data/user/0/.../files/...` |
| 渲染图片 | 直接 `file:///` | 需要 `Capacitor.convertFileSrc()` |

主题包里的 `assets/x.png` 在 Android 要转成 WebView 可加载的 URL（`https://localhost/_capacitor_file_/...`），否则图片全裂。

### 4.3 Markdown 默认拒绝 `file:` 链接

markdown-it 的 `validateLink` 默认不放行 `file:`，自定义主页里的本地图片会被过滤掉。需要在 `markdown.js` 里扩展，并同步放开 DOMPurify 的 `ALLOWED_URI_REGEXP`。

### 4.4 设置存储

桌面写 `settings.json`；Android 用 `localStorage`（或 Preferences 插件）即可，但要**同步写入**，因为渲染层很多逻辑会立刻 `getSettings()` 读回。

## 5. 移动端 UI

### 5.1 上下白边

**现象**：状态栏和导航栏是白色，和深色主题割裂。

**解决**：

- `styles.xml` 里给 `statusBarColor` / `navigationBarColor` 预设主题色，冷启动不闪白
- 运行时按当前主题调 `Window#setStatusBarColor` + `SYSTEM_UI_FLAG_LIGHT_STATUS_BAR`
- `viewport` 加 `viewport-fit=cover`，用 `env(safe-area-inset-*)` 处理刘海
- `html/body/.app` 背景设成 `var(--bg)`，WebView 回弹时不露白

### 5.2 软键盘遮挡编辑器

`android:windowSoftInputMode="adjustResize"`，让 WebView 视口收缩而不是整体上推。CodeMirror 需要配合 `visualViewport` 处理，否则光标会落在键盘下面。

### 5.3 桌面布局直接搬到手机不能用

- 侧栏只在放不下时改抽屉（`@media (max-width: 620px)`：fixed + translateX + 遮罩），
  左上角品牌图标打开、点内容区关闭；620–760px 仍保持两列
- 分栏模式在窄屏退化为单栏，并隐藏「分栏」按钮
- 格式化工具栏不要横向滚动：≤760px 收成「标题 / 格式 / 颜色 / 插入」几个下拉 +
  撤销 / 恢复 / 保存，触控目标 ≥ 30–44 px
- 插件入口放格式栏：桌面每个插件一个图标按钮，手机收成一个「插件」下拉；不要再放右下角浮动区，也不要放标题栏
- 悬停才出现的浮层（表格工具条、代码复制）在触屏上要改成「点选后固定显示」

### 5.4 整页横向溢出：`.app` 的隐式网格列

**现象**：手机上标题栏、标签栏、欢迎页一起被裁掉一截，页面能左右拖动；截图里
左边缘的文字只剩半个字。

**原因**：`.app` 是 `display: grid`，只写了 `grid-template-rows`，没有写列。
隐式列是 `auto`，按子项（标题栏 / `.shell`）的 max-content 定宽，于是整列
被撑到 500px+，而视口只有 360–440px。`width: 100vw` 并不能约束网格轨道。

**解决**：

```css
.app {
  grid-template-columns: minmax(0, 1fr); /* 关键：显式列并把下限设为 0 */
  width: 100%;
  max-width: 100vw;
}
html { overflow-x: clip; }
body { overflow: hidden; }
```

宽表格在手机上再用 `display: block; overflow-x: auto` 让它自己滚，代码块保持
`pre code` 内部滚动；页面本身永远 `scrollWidth === clientWidth`。

**预防**：任何「单屏壳」都不能依赖隐式网格轨道；新增 `grid` 容器时先写列定义。

### 5.5 窄屏要收纳按钮，而不是让工具栏滚动

手机宽度下把全部按钮排开一定会挤爆，正确做法是把次要入口收进菜单，
把宽度让给标题、标签和正文：

- 标题栏：≤760px 只留主题切换 + 「更多」，主题工作室 / 帮助 / 设置进
  `#appMenuBtn` 的 `#appMenu`（按钮用 `data-app-action` 转发现有按钮的点击）。
- 格式栏：≤760px 只留标题级别、格式（`#formatMoreBtn`）、颜色、插入、插件、撤销、恢复、保存；
  加粗 / 斜体 / 删除线 / 行内代码 / 链接 / 列表 / 引用 / 任务 / 公式全部进
  `#formatMoreBtn` 的 `#formatMenu`；插件元素与脚本按钮进 `#pluginMenuBtn` 的 `#pluginMenu`。
- 状态栏：手机只留字数、同步、编码；`charCount` / `readTime` / 行尾 / 语言隐藏。
- 设置项：≤760px `.setting-row` 改为纵向堆叠，标签与滑杆/开关各占整行。
- 快捷键提示（`Ctrl N` 等）在 `[data-compact]` 下全部隐藏。
- Android 不再预留 `--window-controls: 146px`（那是 Windows 窗口按钮的位置）。

**验收**：320 / 360 / 416 宽度下，格式栏 `scrollWidth === clientWidth`，
标题栏标题不被挤成省略号，欢迎页两个主按钮并排且完整可见。

### 5.4 桌面专属入口要藏掉

文件关联徽章、注册表设置、"在资源管理器中显示" 在移动端没有意义，用 `platform-android` 类批量隐藏，避免用户点了没反应。

## 6. 打包与签名

### 6.1 `keystore.properties` 带 BOM → 构建失败

**现象**

```
A problem occurred evaluating project ':app'.
> Cannot convert 'null' to File.
```

**原因**：用 PowerShell `Set-Content -Encoding utf8` 写出的属性文件带 BOM，`java.util.Properties` 把第一行的 key 读成 `\uFEFFstoreFile`，于是 `storeFile` 为 null。

**解决**：用编辑工具写，或显式去掉 BOM；本次用 Node 写纯 UTF-8。

### 6.2 签名配置要能「没有 keystore 也能构建」

`app/build.gradle` 里用 `keystorePropertiesFile.exists()` 判断，缺失时跳过签名，保证 clone 下来就能出 debug 包。

### 6.3 图标与启动图

`assets/icon-512.png` 用脚本生成各密度 `mipmap`（48/72/96/144/192）和 `ic_launcher_foreground`（看清 adaptive icon 的 108dp 安全区），启动图按各 `drawable-*` 尺寸重绘。别手工截图，脚本生成可重复。

### 6.4 版本号

`versionCode` 每次安装递增（本次 1→4），否则覆盖安装会失败。

## 7. 测试

### 7.1 没有真机时用「模拟壳」

`scripts/android-harness/` 是一个 Electron 小程序：伪造 `window.Capacitor.Plugins`，把文件操作落到本地目录，用 CDP 驱动。

```powershell
electron scripts/android-harness --user-data-dir=scripts/android-harness/profile --remote-debugging-port=9225
```

它验证了：启动、打开文档、编辑保存、新建另存、设置持久化、主题包导入、`.zip` 直接打开。

**但它验证不了**：真实 SAF 行为、软键盘、系统打印、HarmonyOS 兼容层。这些必须真机。

### 7.2 用环境变量模拟失败路径

在模拟壳里加开关，分别复现三条保存路径：

```js
if (process.env.HARNESS_READONLY === '1') throw new Error('WRITE_DENIED: Permission Denial');
if (process.env.HARNESS_NO_SAVER === '1') throw new Error('NO_SAVER');
```

否则「只读」「另存为不可用」这两条分支永远测不到，而它们恰恰是真机上最容易出问题的路径。

## 8. 平台能力差异（本次结论）

| 能力 | 桌面 | Android |
| --- | --- | --- |
| 打开 / 保存 | 原生对话框 | SAF（可能只读，必须兜底） |
| 另存为 | 原生对话框 | `ACTION_CREATE_DOCUMENT`（可能不存在） |
| 导出 PDF | `printToPDF` | 系统打印 |
| 插入图片 | 相对路径引用 | data URL（体积受限） |
| 文档内相对路径图片 | ✅ | ❌ SAF 无目录权限 |
| 默认打开方式 | 注册表 + 系统设置 | Manifest intent-filter |
| 单实例 | 锁 + 二次启动路由 | `singleTask` + `onNewIntent` |
| 窗口图标 | 可动态换 | 不可改（应用图标由系统管理） |
| 拖拽导入 | ✅ | ❌ 无拖拽 |
