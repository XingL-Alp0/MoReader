## 1. 一句话与当前状态

墨阅是一个本地 Markdown 阅读/编辑器：Electron 桌面版（Windows）+ Capacitor Android 版共用同一套渲染层；纯文本存储，不锁定格式。

当前状态（截至本文）：

- 桌面：`npm run dev` 可用；`npm run dist` 能产出 NSIS 安装包（**需明确指令才打包**）。
- Android：`npm run android:release` 可产出签名 APK，最近产物 `release/MoRead-Android-1.1.0.apk`（versionCode 11）。
- 插件：桌面端支持启用/停用、`.zip` 安装/覆盖更新/卸载、「重新扫描」热重载；Android 没有插件桥。
- 验证：有插件管理器单元测试 `npm run test:plugins`；其余靠 CDP 冒烟 + 目视，没有 CI。
- 渲染层单文件 `dist/renderer.js` 约 2.5 MB；Mermaid（约 5 MB）单独放 `dist/vendor/mermaid.min.js` 按需加载。
- **本仓库不是 git 仓库**（没有 `.git`），没有版本历史可回滚，改动前请自行备份或用编辑工具小步改。

## 4. 运行、构建、打包

### 环境要求

- Node.js 20+
- 打包 Android：**JDK 21**（JDK 25 会报 `Unsupported class file major version 69`）、Android SDK（`platforms;android-36`、`build-tools;36.0.0`、`platform-tools`）、`ANDROID_HOME`。
  本机 SDK 在 `D:\dev\tools\android-sdk`，JDK 在 `C:\Program Files\Java\jdk-21.0.11`。
- Gradle 走腾讯镜像、Maven 走阿里云镜像（已写入 `android/`，见踩坑记录）。

### 常用命令

```powershell
npm install
npm run build          # esbuild 打包 renderer + 复制 vendor（不打包应用）
npm run test:plugins   # 插件管理器单元测试（发现/加载/热重载/zip 安装/卸载）
npm run dev            # = scripts/start-dev.ps1：build 后直接启动 Electron 开发版
npm run pack           # 免安装目录 release/win-unpacked（需指令）
npm run dist           # NSIS 安装包（需指令）
npm run android:sync   # build + cap sync + 清理 sourcemap
npm run android:build  # debug APK
npm run android:debug  # 构建/安装 debug APK，启动并把 WebView 调试端口转发到 9333
npm run android:release# 签名 release APK
```

### 开发启动脚本

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-dev.ps1 `
  -File "examples\示例文档.md" -DebugPort 9223 -UserDataDir "tmp\profile" -SkipBuild -Log
```

参数：`-File` 打开文档、`-DebugPort` 开 CDP、`-UserDataDir` 隔离配置（**避免与已安装版抢单实例锁**）、`-ImportTheme` 启动即导入主题包、`-SkipBuild`、`-Log`。

### 6.2 主题包（`theme.json`，格式 `moread-theme@2`）

```json
{
  "format": "moread-theme",
  "version": 2,
  "name": "我的墨阅主题",
  "home": { "enabled": true },
  "style": { "enabled": true },
  "theme": {
    "mode": "light",
    "primary": "#c4562d",
    "secondary": "#b4873b",
    "componentColors": { "appBg": "#f0e8de" },
    "brandIcon": { "type": "preset", "value": "default" },

    "customButtons": [],

```

ZIP 布局：`theme.json`、`style.css`、`home.md`、`assets/*`。
导入解压到 `%APPDATA%\MoRead\theme-assets\packs\<packId>\`（每个主题包独立目录）。
主题包库里的 `payload` 只存**可移植**内容（`assets/x`，不存 `file://`），应用时才按平台转换。

### 6.3 组件颜色（`src/renderer/theme.js` 的 `COMPONENT_COLORS`，共 22 项）

背景：`appBg`、`titlebarBg`、`sidebarBg`、`surfaceBg`、`editorBg`、`paperBg`、`paperSoft`、`statusBg`
文字：`ink`、`inkSoft`、`muted`、`faint`
线条：`line`、`lineSoft`
内容：`codeBg`、`codeInk`、`codeHead`、`tableHead`、`quoteBg`、`selection`
图表：`diagramPrimary`、`diagramSecondary`（CSS 变量 `--diagram-primary/secondary`）

`generateComponentColors(primary, secondary, theme)` 从主题色生成整表；`componentColorsAuto=true` 时随主题/深浅色重算。

### 6.4 Mermaid 图表标记

写在 `mermaid` 代码块的第一行（注释），例如：

```
%% moread:mindmap theme=moss layout=tree direction=TB
mindmap
  root((墨阅))
```

- `theme=<preset>` 或 `primary=#.. secondary=#..`：单图配色覆盖（不写则跟随主题）
- `layout=tree`（`direction=LR` 默认 / `TB`）：以流程图方向渲染同一棵 mindmap 树；不写即 Mermaid 原生发散布局
- 其他渲染器会把它当普通注释忽略，源码保持可移植
- 渲染入口：`prepareMermaidRender(source)` → `{ source, layout }`
- 结构编辑：`canStructureEdit()` 对所有已识别图种返回 true。`mindmap` / `flowchart` 走
  `parseMindmap` / `parseFlowchart` 的节点级编辑；`sequence` / `class` / `state` / `pie` /
  `gantt` / `journey` / `er` 走 `renderMermaidLineStructure()` 的**逐行语句编辑**
  （每行一条 Mermaid 语句，支持新增/删除/上移/下移，实时预览），不做语义重写，避免改坏
  复杂语法；`unknown` 仍只给源码面板。

### 6.4.1 可视化模式的不可编辑块

- `.mermaid-figure` / `.math-block` / `.code-block` / `.table-shell` / `.html-preview` / `hr`
  是原子块。进入可视化模式时 `ensureVisualCaretSpacers()` 会在每个这样的顶层块后补一个
  `.visual-caret-spacer` 空段落，让光标可以落在块后（块本身 `contenteditable=false`）。
- 空 spacer 在 `serializeVisualMarkdown()` 里删除；用户在里面输入后保留为普通段落。
  不要给列表/引用内部的块加 spacer，否则往返会改变 Markdown 结构。

### 6.5 收藏夹与笔记夹

- 收藏夹只存路径，不复制文件：`favorites: [{ path, name, addedAt }]`。桌面路径是绝对路径，
  Android 是 `content://` 或 `file://`。点击收藏项直接 `openPath(path)`。
- 添加收藏有两种入口：`收藏当前`（需要文档已保存）与 `添加路径…`（`favorites:pick`，
  桌面多选文件对话框，Android 走 `pickFiles`，只返回路径、不读正文）；两侧都会显示
  显示名 + 路径两行，同名文件可区分。
- 笔记夹的正文是**真实 Markdown 文件**：
  - 桌面：`<userData>/notes/<id>.md`（`notes:create` 写入、`notes:remove` 删除）。
  - Android：`files/notes/<id>.md`（通过 `writeAppFile` / `removeAppDir`）。
- `noteEntries` 只存元数据 `{ id, type: 'folder'|'note', name, parentId, path, updatedAt }`；
  不要把 `content` 写回设置。旧版本的 `content` 会在第一次 `notes:get` 时自动迁移成文件。
- 笔记文件按 id 命名，显示名来自 `noteEntries.name`；打开笔记后 `doc.name` 用显示名，
  不随文件 basename 变化；笔记文件不进入「最近打开」。
- 笔记夹导出 ZIP 时按 `parentId` 还原文件夹层级，重名自动加后缀。
- 文件夹的「⋯」菜单提供 `新建子笔记` / `新建子文件夹`，可以在任意深度继续嵌套；
  顶层按钮只创建根级条目。
- 分享：Android `shareFile()` 走 `shareSaved`（FileProvider + 系统分享面板），
  文本走 Capacitor `Share`；桌面 `share:text` 只复制到剪贴板，不再自动打开 `mailto:`。
- 内置指南：首启时 `seedGuideNotes()` 把 `guides.generated.js` 里的四篇指南通过 `createNote({name, content})` 写进笔记夹（桌面写 `<userData>/notes/`，Android 写应用私有目录），完成后置 `guidesSeeded`；按名字去重，用户删除后不会自动恢复。

### 6.6 插件系统

- 目录：应用目录 `plugins/<id>/` 与用户目录 `<userData>/plugins/<id>/`；同 id 用户目录覆盖应用目录（安装总是写入用户目录）。
- 清单：`plugin.json`，`id` 需匹配 `^[a-z][a-z0-9._-]{1,63}$`，`entry` 默认 `index.js`；其余字段：name/version/author/icon（图标文件相对路径，或旧版短字符）/iconFile/description/permissions（仅声明，不校验）/resources/elements（含 fields）/buttons。`plugin.json` 允许 UTF-8 BOM。
- 运行：入口在 `vm` 上下文执行（顶层 1 秒超时，只允许插件目录内的相对 `require`），可导出 `activate(plugin)` / `deactivate()`。`vm` 不是安全边界，只应启用可信插件。
- 状态：`disabledPlugins` 存停用 id，`trustedButtons` 存已确认的脚本按钮 id；列表状态来自 `loaded` 与 `errors`（失败原因会显示在设置页）。
- 安装/卸载/热重载：`plugins:install` 读 zip（`plugin.json` 在根或唯一一级目录），校验后解到 `<userData>/plugins/<id>`（临时目录替换，覆盖需 `overwrite`）。安装**必须**带图标文件：`normalizeManifest()` 接 `icon` 路径（或 `iconFile`），`installFromZip()` 校验它存在且不越界，缺失直接拒绝；`plugins:uninstall` 只允许用户目录；`plugins:reload` = 卸载全部 + 重扫 + 重载入口，改 `index.js` 后点「重新扫描」即可生效。
- 图标：`icon` 可以是 `assets/icon.svg` 这类路径，也接受 `{ path }` / `{ file }`；`normalizeIconFile()` 只认 SVG/PNG/JPEG/WebP 且路径在插件目录内。`list()` 用 `iconUrl()` 把文件转成 `file://` URL（≤512 KB、realpath 不越界），并给出 `iconType`；渲染层 SVG 用 `mask-image` 跟随主题色，位图用 `<img>`。旧版短字符 / emoji 保留为 `icon` 回退，目录形式的旧插件仍能显示。
- 渲染：`registerMarkdownElement(name, renderer)` 注册 `[name k=v]` 内联语法；属性进 HTML 前转义、进 CSS/`style` 前净化。插件脚本按钮 id 形如 `plugin:<插件 id>:<按钮 id>`，由格式栏的插件入口直接调用，**不再合并进** `customButtons`；首次运行会确认。
- 资源：`plugin.json` 的 `resources: { key: 相对路径 }`（最多 32 个、单文件 8 MB、禁止 `..`/绝对路径）由主进程校验后转成 `file://` URL；模板里用 `{resource:key}` 引用（HTML 与 CSS 均可），未声明/缺失/越界的文件渲染为空。资源随插件安装落在 `<userData>/plugins/<id>/`，导出 HTML/PDF 后换机器会缺图。
- 格式栏插件入口：启用且声明了 `elements` 或 `buttons` 的插件出现在格式栏。
  - 桌面（>760px）：`renderPluginButtons()` 为**每个插件**渲染一个 `#formatPlugins` 图标按钮
    （图标来自 `iconUrl`），点开只列该插件的元素与脚本按钮。
  - 手机（≤760px）：只显示 `#pluginMenuBtn`（插头 + 「插件」），下拉按插件分组列出全部动作。
  - 元素声明了 `fields`（text/textarea/color/select/number/boolean + options）时先弹表单编辑，
    确认后插入带默认值的 `[name key="value"]`，未声明字段时按 `defaults` 自动推导。
    停用/卸载即时移除；没有任何可执行项的插件不占位置。它不是标题栏入口，也不在右下角浮动区。
- 插件脚本按钮不再写入 `settings.customButtons`；`customButtons` 只保留用户 / 主题包自己的
  按钮，浮动 `#customDock` 只渲染这些按钮。`syncPluginButtons()` 只做清理，
  `renderPluginButtons()` 根据宽度在「每插件一个图标」与「手机插件总菜单」之间切换。
- 插入 UI：`pluginElementDialog`（`#pluginElementFields` 动态生成、`#pluginElementInsertBtn` 提交）只负责生成行内语法；多行输入压成一行，清空字段写 `key=""`。
- 管理界面：`#pluginList` 由 `renderPluginList()` 重建，卡片包含图标、名称/版本、作者、元素/按钮/命令/资源数量、来源与状态标签以及加载失败原因；`#pluginSearch` 按名称/作者/ID/描述搜索，`#pluginFilter` 提供全部/已启用/已停用/异常四个筛选（`aria-pressed` 表示当前项），`#pluginSummary` 汇总「共 N 个 · 已启用 M · 加载失败 K · 筛选后 J」；「详情」展开 `pluginDetailPanel()`（元素与字段数、按钮 id、命令与分组、权限、入口、插件目录，附「在文件夹中显示」；用户插件另有「卸载插件」，内置插件提示只能停用）。搜索词、筛选与展开状态存在渲染层 `state.pluginQuery` / `pluginFilter` / `pluginDetails`，不写入设置；安装成功后重置筛选，重新扫描后保留。Android 没有插件桥时整块替换为「当前平台不支持插件管理」，工具栏与汇总一起移除。
- 插件命令（`commands`）：清单字段 `{ id, label, icon, group, description, script }`，`group` ∈ `import` / `export` / `tools`（未知值落回 `tools`），`id` 需匹配 `^[a-z][a-z0-9._-]{1,63}$`；`normalizeManifest()` 截断 label/script 并按组过滤。渲染层 `renderPluginCommands()` 在 `applyPlugins()` 时重建三个容器：`#morePluginImport`（「更多 → 分享当前文档」下面）、`#morePluginExport`（内置三种导出后面）、`#morePluginTools`（「从磁盘重新载入」后面），无内容时整组隐藏；`import` 组同时镜像到欢迎页的 `#welcomePluginActions`（「新建文档 / 打开文件」下面，未打开文档也能导入），按钮使用 `btn btn-ghost btn-small` 样式。命令按钮 id 形如 `plugin:<插件 id>:<命令 id>`，点击走 `runCustomScript()`（首次确认、`trustedButtons` 记录），`openMoreMenu()` 在没有文档时禁用 `export` 组。停用/卸载插件后 `applyPlugins()` 立即清理菜单项与欢迎页按钮。
- 命令脚本 API：`app.pickFile({ title, extensions })` → 主进程 `dialog:pick-file`（扩展名白名单、单文件、记住 lastDirectory，返回 `{ path, name, extension, size }`）；`app.importDocx(path)` → `docx:import`；`app.createDocument(content, name)` 用 `makeDoc()` 建未保存文档并激活；导出仍复用 `exportHtml` / `exportPdf` / `exportText`。
- Word 导入：`src/main/docx.js` 的 `docxToMarkdown(buffer)` 用 `readZip()` 取 `word/document.xml`（另读 `word/styles.xml` 解析样式里的编号），交给 `src/shared/docx-markdown.js` 的 `convertDocumentXml()` 遍历 `w:p` / `w:tbl` / `w:sdt`：标题（Heading 1–6 / Title / Subtitle）、粗体/斜体/删除线/等宽字体、列表（统一 `-`）、引用、简单表格；图片计入 warning、域与脚注忽略。只接受 `.docx` / `.docm`（`.doc` 提示另存为），上限 32 MB，测试见 `scripts/test-docx.js`。
- 清单规则共享：`src/shared/plugin-manifest.js` 集中 `normalizeManifest()`、ID/资源/图标/字段/命令规则与各上限，主进程 `plugins.js` require 它，Android 宿主用 esbuild 打进渲染层，两端不会漂移。
- 界面脚本（`renderer`）：清单新增可选 `renderer`（相对 `.js`，≤512 KB），桌面由 `plugins:renderer-source` IPC 读取源码、Android 由宿主 `rendererSource()` 返回；渲染层 `syncPluginRenderers()` 在 `applyPlugins()` 后按启用状态执行一次，包成 `module/exports/plugin/app/markdown` 的 `new Function`（与应用同权限、无沙箱），停用/卸载调用 `deactivate()` 并清理。安装时校验文件存在与大小；示例 `plugins/moread-en/` 用它做界面翻译（`release/en.zip`）。
- Android 插件宿主：Android 没有 Node，`src/renderer/plugins/android-host.js` 提供与桌面同形的 `api.plugins`（`list/reload/setEnabled/install/uninstall/openFolder`）。存储为应用私有目录 `files/plugins/<id>/` + `files/plugins/index.json`；用 `MoReadFiles` 的 `appFileUri`/`read`/`writeAppFile`/`removeAppDir` 读写，安装用 `pick({mime:'application/zip'})` + `fflate unzipSync`（沿用桌面限额，条目数/总大小也校验），冲突返回 `{ conflict, id, existing, filePath }` 供覆盖确认复用；资源与图标经 `convertFileSrc()` 转成本地服务 URL。入口脚本用 `new Function("module","exports","require","plugin","console", …)` 执行（`require` 直接抛错），`activate/deactivate` 与桌面一致，**不做沙箱**，由用户自担信任。Android 隐藏「打开插件目录」与「在文件夹中显示」；`pickFile`/`importDocx` 也在适配层实现，Word 导入复用 `convertDocumentXml()`（fflate 解包）。单测见 `scripts/test-plugin-host.js`，端到端用 `scripts/android-harness`（模拟 Capacitor 桥）。

## 9. 约定与已踩过的坑（改代码前必读）

1. **不要用 PowerShell 读写文本文件**。`Get-Content`/`Set-Content` 按 cp936 解码 UTF-8 会不可逆乱码（本项目的 `app.js`、`README.md` 都被毁过）。只用编辑工具改文件；`.ps1` 必须存 UTF-8 with BOM。
2. **未收到明确指令不要打包**（`npm run dist` / `pack` / electron-builder / 重装）。日常验证只用 `scripts/start-dev.ps1`。Android APK 构建同理，按需再出。
3. **适配层不要假设 `path` 是字符串**：新建文档的 `doc.path` 是 `null`，先 `String(payload.path || "")`，否则保存报 `Cannot read properties of null`。
4. **大文件不要用 `atob`**：约 2 MB 的主题包会让渲染进程崩溃；`android.js` 用查表 Base64 解码，`bytesToBase64` 分块处理。
5. **结构编辑的顺序**：先 `pushMermaidStructure()`（写回源码）再 `renderMermaidStructure()`（按源码重建 UI），反过来会丢掉刚加的节点。
6. **CodeMirror 主题**：base theme 的选择器是双类（`.ͼ1 .cm-content`），行号栏/当前行高亮必须 `!important`；`.cm-content` 的 `padding` 与 `.cm-scroller` 的 `line-height` 同样会被 base theme 覆盖，必须 `!important` 才能生效。行号栏**不要**自己加 `padding-top`：CodeMirror 已按 `paddingTop` 给 gutter 元素算好偏移，再加一次会让整列行号下移（踩过，表现为「行号比正文低 26px」）。编辑模式限宽时把 `max-width` 放在 `.cm-editor` 上（行号栏一起居中），不要只给 `.cm-content` 居中（行号会留在面板左缘）。同时用 `themeCompartment` 切 `EditorView.darkTheme`。
7. **悬停浮层**：表格工具条靠 `pointerenter/leave` 延迟 320ms 关闭 + `.table-toolbar-open` 类，不能只靠 `:hover`。
8. **主题包脏比较**：`currentPackPayload()` 必须先用 `serializeAssetRefs()` 转回 `assets/x` 再比较，否则含图片的 CSS 永远显示「有未保存修改」。
9. **导出某套主题包**要用它自己的 payload/assets，不能借用当前设置的资源映射。
10. **`.cm-content` 是虚拟滚动的**，`innerText` 只含可视行；验证「源码里有没有某段」要看保存后的文件，别用 `innerText` 判断。
11. **打包 Android 必须 JDK 21**，且 `JAVA_HOME` 指向它（Gradle 认 `JAVA_HOME` 而不是 PATH）。
12. `start-dev.ps1` 会移除 `ELECTRON_RUN_AS_NODE`，否则 Electron 会以 Node 模式启动。
13. `normalizeManifest()` 必须把插件目录 `dir` 一起返回，`PluginManager.load()` 依赖它定位入口；丢掉后表现为插件列表能发现、但加载全部失败。
14. 插件自定义元素的属性解析与 `{placeholder}` 替换写在 `markdown.js` / `app.js`，正则里不要再给 `\s`、`\w`、`\{` 多加一层反斜杠，否则属性永远解析不出来。
15. `index.html` 里的未闭合 `<button>` 会把后面的按钮吞成属性（撤销/恢复按钮就是这样丢的），改完用标签计数或 CDP 检查 DOM。
16. 笔记正文必须落盘；`noteEntries` 只存元数据。不要把 `content` 长期写回设置，也不要把笔记文件塞进「最近打开」（否则最近列表里会出现一堆 `<uuid>.md`）。
17. 桌面分享不要自动 `mailto:`；没有邮件客户端的机器会静默失败。Android 分享文件走 `shareSaved`（FileProvider），不要直接 `file://` Intent。
18. Android 调试要先把设备点亮/解锁；否则 `/json` 能连上但页面不渲染。`npm run android:debug` 会构建 debug APK、安装并转发 WebView devtools 到 `9333`。
19. 插件按钮与主题包按钮共用 `settings.customButtons`：插件按钮 id 以 `plugin:` 开头，合并/清理都依赖它；切换主题包后要重新合并插件按钮，否则会被主题包覆盖。
20. 插件元素模板里，占位符可能落在 `style="..."` 内；只按 HTML 转义会漏掉 CSS 注入（实测能塞 `position:fixed`）。必须按占位符上下文分别走 HTML 转义 / CSS 净化。
21. 可视化编辑（contenteditable）的撤销/恢复不能调用 CodeMirror 的 `undo(view)`：它看不到可视化 DOM 的编辑，按钮会一直 `disabled`，移动端等于没有撤销。`runHistory()` 在 `state.isVisualEditing` 时先 `dom.preview.focus()` 再 `document.execCommand('undo'|'redo')`，成功后置脏并 `scheduleVisualSync()`；按钮在可视化模式下保持可用，不按 CodeMirror 的 `undoDepth` 判断。
22. 图表编辑入口除了双击，还有 `.mermaid-edit` 按钮（`markdown.js` 生成、`handlePreviewClick` 处理）；触屏上双击不可靠，新增入口时不要只绑 `dblclick`。
23. 窄屏格式栏是「标题 / 格式 / 颜色 / 插入 / 插件几个下拉 + 撤销/恢复/保存」，`flex-wrap: wrap` 只是兜底；不要再把单个格式按钮平铺回窄屏，也不要改回 `overflow-x:auto`（横向滚动会把撤销 / 恢复 / 保存挤出屏幕）。
24. 插件入口在格式栏：桌面每个插件一个图标按钮（`#formatPlugins`），手机一个「插件」总菜单（`#pluginMenuBtn`）；和格式 / 插入 / 颜色同一级菜单栏。不要放标题栏或右下角浮动区。新安装插件包必须带 `icon` 图标文件（SVG/PNG/JPEG/WebP），旧目录插件可回退字符图标。脚本按钮不要写回 `settings.customButtons`。
25. 侧栏开关只保留左上角 `#brandBtn`；`#sidebarToggle` / `#mobileSidebarBtn` 已移除。620px 以下才是抽屉，620–760px 保持两列；workspace 的捕获点击只在抽屉模式生效。
26. 可视化模式的图表/公式/代码块/表格/`hr` 是原子块，光标落不到块后；`ensureVisualCaretSpacers()` 会给每个顶层原子块补 `.visual-caret-spacer`，空 spacer 必须在序列化前删掉。不要给列表/引用内部的原子块补，否则会改变 Markdown 结构。

## 12. 已知限制 / 可改进

- Mermaid 结构编辑只支持单根 mindmap 与「无子图、无 classDef、无链式连线」的 flowchart；其余走源码编辑。
- 树形布局（LR/TB）宽图需要横向滚动；TB 渲染后自动居中。
- 主题包里的图片在删除主题包时会清理其私有目录；但通过「插入图片」加到主页的图片落在 `theme-assets/home/`，会残留。
- 插件只在桌面端发现与加载（`plugins/` 或用户数据目录），Android 适配层尚未实现插件管理；插件入口脚本限制 2 MB，运行在 `vm` 沙箱中。沙箱只拦截外部依赖与目录外文件，**不防恶意代码**，所以只应启用可信插件。
- 插件可安装 `.zip`（用户目录，可在设置里卸载）；主题包可以携带脚本按钮，导入时会确认，脚本首次运行也会显示脚本内容并要求确认。插件元素里由文档属性填入 CSS 的部分会做净化，但插件自身的 HTML/CSS 等同于本地代码，不做能力限制。
- 插件资源（`resources`）以 `file://` 引用，导出 HTML/PDF 后在别的机器打开会缺图；插件元素本身也依赖运行时注册，导出后只剩 HTML 快照。
- 只有插件管理器有单元测试（`npm run test:plugins`），没有 CI；没有安装包代码签名。
- Android 端未在真机验证过本轮功能（图表布局、主题包库、流程图连线）。
- 主题包导入目前串行解压，超大包（>24 MB 图片）会被拒绝。
